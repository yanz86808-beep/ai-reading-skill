# AI Reading Skill

[English](README.md) | 简体中文

AI Reading 是一个面向 ChatGPT 与 Codex 的阅读工作流 Skill。它帮助读者核验书籍信息、真正理解关键概念、检验观点边界，并把可靠洞察转化为可复用资产，而不是根据二手摘要假装“读完”一本书。

## 核心能力

AI Reading 包含四个既可独立运行、又能连续衔接的阶段：

1. **狩猎定位**：确认阅读目标、材料覆盖范围、读者情境和最值得追踪的问题。
2. **费曼吃透**：让读者把概念讲到 6 岁孩子也能听懂，并通过纠偏和复述形成自己的版本。
3. **观点压力测试**：先钢人化原观点，再根据主张类型选择 2–4 个不重复的证据视角；复杂或高风险主张触发四角检验。
4. **资产转化**：把已经核验的理解转成检查表、知识卡片、培训大纲或指定渠道内容。

用户可以从任意阶段开始，也可以说“下一阶段”继续。缺少前序产物时，Skill 会补齐当前阶段所需的最小可信基础，而不会要求重新跑完整流程。

## 适用场景

- 非虚构、管理、心理学和方法类书籍
- 文学、小说与多重文本解读
- 历史、传记、哲学和科普作品
- 用户提供局部合法节选的深度阅读
- 费曼学习、批判性分析和读书资产制作

## 输入条件

AI Reading 不要求用户先上传整本书。以下信息可以组合提供：

| 输入 | 是否必需 | 说明 |
|---|---:|---|
| 书籍或概念 | 是 | 提供书名、作者、ISBN、封面或要学习的概念之一。书名有歧义时，Skill 会先确认作者或版本。 |
| 阅读目标 | 建议 | 例如理解概念、解决问题、研究论证、体验文学作品或制作内容。未提供时使用通用阅读目标，并明确假设。 |
| 当前阶段 | 否 | 可指定阶段一至四；未指定时默认从阶段一开始。也可以只说“下一阶段”继承当前阅读状态。 |
| 原书材料 | 否 | 可以提供合法节选、目录、章节或关键页。没有原文时，Skill 会使用可靠公开来源建立证据受限的最小基础。 |
| 读者情境 | 否 | 可提供角色、具体问题、可行动范围和限制。只使用用户明确提供的信息，不推断收入、健康、政治立场等敏感特征。 |
| 输出控制 | 否 | 可指定简版、标准版、深度版、是否剧透、目标渠道或资产类型。 |

### 材料条件

- **已有任务所需原文**：以用户材料为主要依据，只在身份、版本、争议或当前共识需要核验时补充来源。
- **只有公开资料**：使用作者、出版社、论文和权威机构等来源；明确没有完整覆盖原书。
- **只有局部节选**：只对实际提供的片段作结论，不外推成全书完整观点。
- **冷门新书或资料不足**：先确认身份并请求目录或合法节选，不根据标题、短视频或二手摘要编造内容。

只有在书籍或目标无法识别，或者完全没有可靠材料支持当前阶段时才会暂停询问。缺少用户粘贴的原文，本身不是阻塞条件。

## 安装

### 推荐：使用 `$skill-installer` 安装

在 Codex 中直接粘贴下面这段提示：

```text
使用 $skill-installer 从以下地址安装 AI Reading Skill：
https://github.com/yanz86808-beep/ai-reading-skill/tree/main/skills/ai-reading
```

安装器会从公开仓库下载 `skills/ai-reading`，并放入当前 Codex 环境配置的 Skill 目录。安装成功后，新开一轮对话并输入 `$ai-reading`。在 Codex CLI 或 IDE 扩展中也可以运行 `/skills` 检查是否出现；如果没有立即刷新，请重启 Codex。

### 手动安装到用户目录

克隆或下载本仓库后，将 [`skills/ai-reading`](skills/ai-reading) 复制到 Codex 用户级 Skill 目录：

```bash
mkdir -p ~/.agents/skills
cp -R skills/ai-reading ~/.agents/skills/ai-reading
```

只复制 `skills/ai-reading`，不要把仓库根目录整体当作 Skill。部分环境使用 `$CODEX_HOME/skills`，默认通常是 `~/.codex/skills`；使用 `$skill-installer` 时会自动选择当前配置目录。

### 仓库级使用

需要让同一仓库的协作者自动发现该 Skill 时，在目标仓库根目录执行：

```bash
mkdir -p .agents/skills
cp -R /path/to/ai-reading-repo/skills/ai-reading .agents/skills/ai-reading
```

Skill 本身不需要 API Key 或额外运行时依赖。执行需要当前信息核验的阅读任务时，宿主 Codex 可能需要联网搜索权限。

## 使用方式

### 调用方式

- **显式调用**：在提示中写 `$ai-reading` 并描述任务。
- **自然触发**：直接提出读书、费曼学习、观点检验、读书笔记或内容资产需求；宿主可根据 Skill 描述自动选择。
- **继续流程**：说“继续”或“下一阶段”，复用当前书籍、读者映射、证据状态和已修正观点。
- **跳转阶段**：直接说“从第二阶段开始”或“只执行阶段三”，无需先完成前序阶段。

## 使用示例

```text
使用 $ai-reading 阅读《思考，快与慢》。
我的目标是减少招聘决策中的认知偏差，只执行阶段一。
```

```text
用费曼法帮我吃透“沉没成本”，直接从第二阶段开始。
```


## 输出条件

| 阶段 | 主要输出 | 交互与完成条件 |
|---|---|---|
| 阶段一：狩猎定位 | 书籍身份与覆盖范围、阅读问题、读者映射、材料范围内的结构或主题、争议、来源与不确定项 | 引导模式完成后暂停，由用户决定继续、跳转或换书。 |
| 阶段二：费曼吃透 | 1–3 个待练概念、一次一个的 6 岁复述问题、纠偏、生活类比和用户确认的“我的版本” | 必须等待用户回答；每个概念最多三轮。报告模式只提供自测材料，不虚构互动。 |
| 阶段三：观点压力测试 | 原观点钢人化、2–4 个非重复视角、每个视角的证据、修正和判定，以及最终适用边界 | 简单方法通常使用 2 个视角，因果或外推主张通常使用 3 个，高风险且同时影响个人、组织、制度和伦理时使用 4 个。 |
| 阶段四：资产转化 | 一个指定或选定的检查表、知识卡片、培训大纲或渠道样稿 | 已指定资产时直接生成一个样稿；未指定时先给精简菜单，不默认批量生成所有渠道。 |

### 输出模式

- **引导模式（默认）**：逐阶段互动，费曼阶段等待用户回答。
- **单阶段模式**：直接执行指定阶段；缺少上游结果时只补齐本阶段需要的最小可信基础。
- **报告模式**：一次性交付研究结果、自测题、压力测试和资产建议，但明确哪些互动尚未发生。
- **长度档位**：简版通常最多 3 个核心框架；标准版通常 3–5 个；深度版增加争议、反例和来源比较。

所有输出必须标明实际材料覆盖范围，并区分原书内容、作者补充、第三方观点和分析推断。Skill 不保证覆盖未获得的全书，也不会把跳过的阶段写成已经完成。

## 材料、证据与版权边界

- 区分原书可核验内容、作者公开补充、第三方解读、AI 推断和未核实信息。
- 优先使用作者、出版社、论文和权威机构等一手来源。
- 不编造章节、案例、实验、数据、页码或引语。
- 不输出可替代原书的逐章复述、大量连续原文或重建式摘要。
- 用户只提供局部材料时，只对实际覆盖范围作出结论。
- AI Reading 提供的是阅读、研究和思考辅助，不替代原书，也不替代专业医疗、法律或金融意见。

详细规则见 [`source-and-copyright-policy.md`](skills/ai-reading/references/source-and-copyright-policy.md)。

## 验证

仓库提供不依赖第三方 gem 的 Ruby 校验脚本：

```bash
ruby scripts/validate_skill.rb
```

校验包括 Skill 元数据、命名、内部引用、`openai.yaml`、行数、公开文件中的本机路径和常见凭据模式。GitHub Actions 会在 push 和 pull request 时运行同一校验。
