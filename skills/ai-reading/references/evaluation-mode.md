# 自动评估模式

仅在用户明确要求测试、回归、比较或自动跑完 AI Reading 流程时使用。目标是验证 Skill 的行为和阶段衔接，不是替用户完成真实学习。

## 与其他模式的边界

- 引导模式的费曼阶段必须等待真人回答。
- 完整报告或专题报告只能提供自测材料，不能假装发生过互动。
- 自动评估模式可以使用“测试读者回答”继续四阶段，但必须始终标记为测试夹具，不能写成用户回答，也不能据此声称用户已经理解。

## 测试设计

按风险选择 2–4 本差异明显的书，至少覆盖两种书籍类型。需要验证跨书型适配时，优先从方法论、文学、历史、科学和哲学中选择。

每本书执行：

1. **阶段一**：建立全书总框架、读者映射和证据范围。
2. **阶段二**：提出一个真正容易误解的概念问题；注入一条合理但有关键错误的测试回答；输出讲清楚处、遗漏或跑偏处、6岁版解释和修正版测试回答。
3. **阶段三**：只使用阶段二修正后的观点作为输入，按主张类型选择2–4个视角并形成更可靠版本。
4. **阶段四**：只使用阶段三的最新可靠版本生成一个资产；资产必须继承证据和边界。

至少有一本书测试“返回阶段二后再进入阶段三”，至少有一本测试直接进入阶段三或阶段四。跳过、返回和直接进入的状态按 [reading-state.md](reading-state.md) 记录。

## 测试夹具格式

```markdown
**测试问题**：[一个概念问题]

**测试读者回答（夹具，不是用户回答）**：[合理但存在关键误解的回答]

**纠偏结果**：
- 讲清楚的地方：
- 遗漏或跑偏处：
- 6岁版解释：
- 修正版测试回答：
```

不要为了让测试容易通过而注入明显荒谬的回答。错误应接近真实读者常见误解，例如概念混淆、因果跳跃、把比喻当事实或把有条件主张绝对化。

## 验收矩阵

每本书逐项判定通过或失败：

- 阶段一是否先建立总框架，而非零散摘要；
- 阶段二纠偏是否针对本书且没有牺牲原意；
- 阶段三是否继承修正版观点，而非退回原始误解；
- 阶段三视角是否随书型和主张变化；
- 阶段四是否继承压力测试后的边界；
- 换书后是否重置书籍身份和读者映射；
- 是否区分原书事实、外部证据、应用推断与测试夹具；
- 是否记录跳过、自动补齐和返回状态；
- 是否出现一票否决问题。

输出必须包含总体通过率、每本书的阶段轨迹、失败证据和修正建议。不能因为流程生成了四个标题就判定通过。

## 停止条件

- 没有足够可靠材料支持书籍身份或待测观点时，记录阻塞，不注入虚构材料；
- 出现一票否决问题时，该书直接判定失败并保留失败样本；
- 测试只授权生成测试结果，不自动授权覆盖运行中的 Skill、提交 Git 或发布 GitHub。
