# 完整阅读报告

用户宽泛地要求“读一本书”时使用。本报告的标准是：看完能复述书的核心、能说明关键材料怎样支撑观点或主题、能获得适合该书型的理解抓手，也知道哪些地方不能照单全收。不是目录摘要，也不是以来源审计代替读书。

## 完成标准

一份标准完整报告只有同时满足以下条件才算完成：

- 有一句话核心命题，并把全书总框架作为第一核心知识点讲透；总框架要解释全书问题、关键模块、彼此关系、运转路径和边界，不是装饰性知识地图；
- 有 3–5 个挂靠总框架的核心模块、论证或主题，每个都说明在整体中的位置，并有作者原意、完整结构和类型适配的支撑材料；
- 支撑材料达到书型要求：方法书讲清“背景 → 过程或关键动作 → 结果 → 它证明什么”，文学使用关键情节、文本依据和叙事作用，哲学还原论证链，历史交代事件与史料，科学说明研究与证据强度；
- 有 2–3 个真正由材料支撑的关键张力、反常识洞察、常见误读或争议；方法论与商业书通常给3个反常识案例，其他书型不机械凑数；
- 有符合书型的知识把手，以及符合阅读意图的3个行动、继续验证问题或再阅读入口；
- 有压力测试和集中式可信度审计；
- 应用型有一个现实应用闭环，其他意图有理解、解释或判断闭环；用户未特别要求业务方案时，现实应用不超过全文 20%。

如果材料不足以完成某一项，继续寻找合法公开材料；仍然不足时明确缺口。不得用泛泛概括假装完成，也不得编造案例细节。

## 内容比例

默认控制重点而非机械计算字数：

- 书本理解约 60%–70%：知识地图、核心框架、类型适配的支撑材料、关键张力和知识把手；
- 挑战与审计约 15%–20%；
- 现实应用不超过 20%。

如果报告里用户业务方案比书中案例更长，说明已经跑偏，必须压缩应用、补足书本内容。用户明确要求“主要帮我应用”时才可以改变比例。

## 案例与证据规则

- 优先选择能代表框架、材料最完整的一个案例讲深，不要罗列多个案例名称。
- 原书或合法节选可直接概括；作者访谈可作为作者公开补充；详细二手材料可以恢复案例脉络，但必须标记为第三方记录。
- 两份二手材料一致仍不是原书直接证据。它提高的是可用信心，不改变来源等级。
- 案例缺少结果或作者结论时写明缺口，不自行补齐。
- 平台运营、技术、医学、法律、投资和科学类书籍，要检查出版后的规则或共识变化。
- 作者经验公式与外部事实分开。类似“X%”“必然成功”“平台给多少流量”的精确说法，没有当前直接证据时放入“有条件成立”“可能过时”或“尚未核实”。

## 书籍类型替换

- 方法论、商业、管理、实用书：使用框架、案例、工具箱、行动清单和验证指标。
- 哲学与思想：使用完整论证链、概念边界、思想实验、作者回应的反对意见和判断原则；不强制现实行动。
- 文学：使用人物关系、关键情节、文本证据、意象、多重解读和再阅读问题；不强行生成经营工具或励志行动清单。
- 历史、传记、纪实：使用时间线、人物选择、环境条件、史料冲突、反事实问题和事后归因边界。
- 科学与科普：使用研究问题、实验设计、发现、复现、证据等级、可证伪问题与当前共识。
