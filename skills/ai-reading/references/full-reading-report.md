# 完整阅读报告

用户宽泛地要求“读一本书”时使用。本报告的标准是：看完能复述书的核心、能讲出案例为什么支持观点、能拿走方法，也知道哪些地方不能照单全收。不是目录摘要，也不是以来源审计代替读书。

## 完成标准

一份标准完整报告只有同时满足以下条件才算完成：

- 有一句话核心命题，并把全书总框架作为第一核心知识点讲透；总框架要解释全书问题、关键模块、彼此关系、运转路径和边界，不是装饰性知识地图；
- 有 3–5 个挂靠总框架的核心模块、论证或方法，每个都说明在整体中的位置，并有作者原意、全部组成和详细书中案例；
- 案例讲清“背景 → 过程或关键动作 → 结果 → 它证明什么”，不能只报案例名称；
- 有 3 个真正由书中证据支撑的反常识结论；
- 有可复用的方法工具箱和 3 条立即行动；
- 有压力测试和集中式可信度审计；
- 有一个现实应用闭环，但用户未特别要求业务方案时不超过全文 20%。

如果材料不足以完成某一项，继续寻找合法公开材料；仍然不足时明确缺口。不得用泛泛概括假装完成，也不得编造案例细节。

## 内容比例

默认控制重点而非机械计算字数：

- 书本理解约 60%–70%：知识地图、核心框架、详细案例、反常识洞察和工具箱；
- 挑战与审计约 15%–20%；
- 现实应用不超过 20%。

如果报告里用户业务方案比书中案例更长，说明已经跑偏，必须压缩应用、补足书本内容。用户明确要求“主要帮我应用”时才可以改变比例。

## 案例与证据规则

- 优先选择能代表框架、材料最完整的一个案例讲深，不要罗列多个案例名称。
- 原书或合法节选可直接概括；作者访谈可作为作者公开补充；详细二手材料可以恢复案例脉络，但必须标记为第三方记录。
- 两份二手材料一致仍不是原书直接证据。它提高的是可用信心，不改变来源等级。
- 案例缺少结果或作者结论时写明缺口，不自行补齐。
- 平台运营、技术、医学、法律、投资和科学类书籍，要检查出版后的规则或共识变化。
- 作者经验公式与外部事实分开。类似“X%”“必然成功”“平台给多少流量”的精确说法，没有当前直接证据时放入“有条件成立”“可能过时”或“尚未核实”。

## 书籍类型替换

- 方法论、商业、管理、实用书：使用框架、案例、工具箱和行动清单。
- 哲学与思想：把“书中案例”替换为完整论证链、思想实验或作者回应的反对意见。
- 文学：替换为人物关系、关键情节、文本证据、意象和多重解读，不强行生成经营工具。
- 历史、传记、纪实：替换为时间线、选择、环境条件、史料冲突和事后归因边界。
- 科学与科普：替换为研究问题、实验设计、发现、复现与当前共识。
